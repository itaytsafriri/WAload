# Supabase Logging Integration

This document describes the Supabase logging integration added to the WAload application.

## Overview

The WAload application now includes comprehensive logging to Supabase for tracking client activities, media processing, and video conversions. This logging system captures detailed information about each media message processed by the application.

## Database Schema

The logging data is stored in the `WAL Clients Log` table with the following structure:

```sql
CREATE TABLE public."WAL Clients Log" (
  id bigint generated by default as identity not null,
  created_at timestamp with time zone not null default now(),
  mac_id text null,
  sender text null,
  mediatype text null,
  autoconverted text null,
  succsesful text null,
  ext text null,
  constraint WAL Clients Log_pkey primary key (id)
);
```

## Components

### 1. SupabaseLoggingService

Located in `Services/SupabaseLoggingService.cs`, this service handles:

- HTTP communication with Supabase REST API
- MAC address extraction for client identification
- Logging of media processing activities
- Connection testing functionality

**Key Methods:**
- `LogClientActivityAsync()` - Logs general client activities
- `LogMediaProcessingAsync()` - Logs media processing results
- `TestConnectionAsync()` - Tests Supabase connection

### 2. MessageQueue Integration

The `MessageQueue` service has been enhanced to include logging:

- Logs successful media message processing
- Logs failed media message processing
- Captures sender information, media type, and file extension
- Tracks processing success/failure status

### 3. VideoProcessingService Integration

The `VideoProcessingService` includes logging for:

- Video conversion attempts
- Image processing attempts
- Conversion success/failure tracking
- File extension and media type logging

## Logged Data

For each media message processed, the following information is logged:

| Field | Description | Example |
|-------|-------------|---------|
| `mac_id` | Client's MAC address (unique identifier) | "A1B2C3D4E5F6" |
| `sender` | Name of the message sender | "John Doe" |
| `mediatype` | Type of media (image, video, audio, document) | "video" |
| `autoconverted` | Whether auto-conversion was applied | "yes"/"no" |
| `succsesful` | Whether processing was successful | "yes"/"no" |
| `ext` | File extension | ".mp4" |

## Usage

The logging is automatically integrated into the application workflow:

1. **Media Message Reception**: When WhatsApp media messages are received, they are automatically logged
2. **Processing Queue**: The MessageQueue logs each processing attempt
3. **Video Conversion**: The VideoProcessingService logs conversion attempts and results

## Testing

To test the Supabase logging connection, you can use the test method:

```csharp
var messageQueue = new MessageQueue();
bool connectionSuccessful = await messageQueue.TestLoggingConnectionAsync();
```

## Error Handling

The logging system includes comprehensive error handling:

- Network connectivity issues are logged to debug output
- Failed API calls are logged with detailed error information
- The application continues to function even if logging fails
- All logging operations are wrapped in try-catch blocks

## Dependencies

The Supabase logging integration requires:

- `supabase-csharp` NuGet package (version 0.13.7)
- `Newtonsoft.Json` for JSON serialization
- `System.Management` for MAC address extraction

## Security

- API credentials are embedded in the service (consider moving to configuration for production)
- MAC addresses are used for client identification
- All HTTP requests use HTTPS
- Error messages are logged locally for debugging

## Monitoring

To monitor the logging system:

1. Check debug output for logging-related messages
2. Monitor Supabase dashboard for incoming log entries
3. Use the test connection method to verify connectivity
4. Review error logs for any connectivity issues
